# Code of Conduct

## The short version

Be decent. Ward is a small open source security project, not a battleground.

## Expected behaviour

- Assume good faith. Most disagreements in security tooling are about
  threat models, not about people.
- Give and take criticism on the work, not the person. "This rule will
  false-positive on X" is useful. "This is amateur" is not.
- Respect that maintainer time is donated. A well-formed issue with a
  reproducible input is worth more than a follow-up asking for an update.

## Unacceptable behaviour

- Harassment, personal attacks, or discriminatory language of any kind.
- Publishing others' private information.
- Deliberately filing misleading reports, or using the issue tracker to
  publish a live vulnerability in Ward rather than reporting it privately.
- Sustained disruption of discussions.

## Responsible use

Ward is a defensive tool and its test fixtures contain real prompt-injection
payloads. They are there so the scanner can be tested against them. Using
this repository to coordinate attacks on systems you do not own or have
permission to test is out of bounds and will get you removed.

## Reporting

Report conduct problems privately to the maintainer through
[GitHub Security Advisories](https://github.com/craigmccart/ward/security/advisories/new)
or by opening a private thread via the repository's contact options. Reports
are handled confidentially.

Security vulnerabilities in Ward itself go through the process in
[SECURITY.md](SECURITY.md), not here.

## Enforcement

The maintainer may edit, hide, or delete comments, and may block accounts,
for behaviour that breaches this document. Decisions are at the maintainer's
discretion and are final.
